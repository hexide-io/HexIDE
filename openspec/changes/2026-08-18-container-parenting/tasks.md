## Phase 4 — Frame becomes a real container at run time

**Goal.** A running form draws a Frame's children inside the Frame, at their stored container-relative coordinates, with VB6-correct .Left/.Top reads, correct tab order, correct option-button grouping and no lost events.

**Gate after this phase.** SHUT. Children are now positioned correctly RELATIVE TO their Frame — not "the runtime is correct", because `Align` is modelled and never read (VBProperties.cs:54, PictureBoxComponentClass.cs:13, VBLoader.cs:57-58), so an Align-ed container is still drawn at its stored position. PictureBox is not a container yet and the designer still places every child at face value.

- [ ] 4.1 Give `VBFrame` its own ControlTheme whose template is the group-box border, the caption, and a named child-host Canvas filling the control's OUTER bounds with `ClipToBounds = true`. SimpleTheme's stock HeaderedContentControl presenter is inset by the border and pushed below the header (VBFrame.cs:8 sets StyleKeyOverride and no VBFrame theme exists), so hosting in it would silently offset every child by a theme-dependent amount.
- [ ] 4.2 Expose the child host as a styled property the component class owns and the template presents — never a NameScope part. `SpawnComponents` builds its canvas before `window.Content` is assigned (VBLoader.cs:151), so no template is applied at load time, and template re-application would orphan children already placed in an old part.
- [ ] 4.3 Add `TryGetChildHost` to `ComponentBaseClass` (HexIDE.Runtime), NOT to `IComponentClass` — HexIDE.Core declares zero third-party dependencies and has no Avalonia reference, and IComponentClass is implemented by add-ins (IHexIdeHost.cs:20).
- [ ] 4.4 Extract the placement recursion shared by `SpawnComponents` (VBLoader.cs:52-63) and `SpawnComponentsForDesigner` (:120-132) into one helper, and DO NOT merge the two methods: the latter is the run-time body of a hosted UserControl (UserControlComponentClass.cs:26-27) and deliberately allocates no interpreter variables and builds no control-array groups.
- [ ] 4.5 Add the source/Handled guard to `AttachedEvents.AttachClick`'s PointerReleased class handler (AttachedEvents.cs:21-24) so a child click does not also raise the container's Click. This must land before anything is nested.
- [ ] 4.6 Map a container's VB6 `Visible` to `Opacity` plus `IsHitTestVisible` rather than to `Visual.IsVisibleProperty` (AvaloniaInteroperability.cs:105). Avalonia never applies a hidden templated control's template, so a hidden container would unrealise its whole subtree and NOTHING inside it would dispatch — not Timer_Timer, not Text1_Change, not Command1_Click — because RuntimeExtensions.ExecuteSub (:10-22) walks the visual tree to find the execution root.
- [ ] 4.7 Make `VBLoader` consult `IsVisual` (IComponentClass.cs:19) and host non-visual components on the form's own canvas regardless of their recorded container, while the model keeps the container so the file round-trips. Set `IsVisible = false` on them, which also fixes the pre-existing visible 28x28 clock icon (VBTimer.axaml:9-12 pins Min/MaxWidth to 28 while VBLoader sets Width = 0).
- [ ] 4.8 Keep the running form's tab order the flat form-wide TabIndex sequence: `ComponentBaseClass.Instantiate` sets TabIndex per control (:50) and Avalonia resolves it among siblings within a navigation scope, so a host canvas must set `KeyboardNavigation.TabNavigation = Continue` or ODBC Log In.frm would tab 13, 12, 14 and only then descend into 0-11.
- [ ] 4.9 Give `ControlArrayGroup` a per-element host in place of its single `Canvas? canvas` field (ControlArrayGroup.cs:23, :36-46, :53-70) so a runtime `Load` clones into the same container as its template. Pin the container-element case (Load on a container clones the control only, :60) as a test with its current behaviour, and add the VB6 question to the open list.
- [ ] 4.10 Headless render tests in HexIDE.Integration.Tests/Views/: a Frame with children renders them nested and clipped; `Text1.Left` inside `Frame1` reads the container-relative value; a Timer inside a hidden Frame still ticks and a TextBox inside one still raises Change; a child click does not fire the container's Click; option buttons in different Frames are different groups; `Frame1.Enabled = False` disables its children.
