# HexIDE design philosophy

HexIDE aims to feel **instantly familiar** to anyone who spent years in Visual Basic 6 — the same
default keybindings, the same menus and toolbars, the same muscle memory — while quietly leaving 1998
behind.

## Three principles

**1. Familiar by default.**
If you knew VB6, you already know HexIDE. Default shortcuts, menu structure, and the form designer
match what your hands expect — you're productive on day one, with nothing to relearn.

**2. Cruft removed or modernised.**
Where VB6 showed its age — dead features, dated dialogs, workarounds for long-gone limitations —
HexIDE drops it or brings it up to date. Never change for its own sake.

**3. Modern touches, folded in gently.**
Conveniences today's developers expect are added *additively and overridably* — they help if you want
them and stay out of the way if you don't. Nothing modern comes at the cost of familiarity.

## The test

For any change, we ask one question:

> Would a 20-year VB6 professional recognise this instantly — and be glad it's better?

If a change can't pass that test, it doesn't ship in the default experience. Anything more adventurous
is opt-in, never forced.
