# A match note calls another document area's shown tab hidden — **CLOSED** (#3814, 2026-11-12)

**Symptom.** Measured on Windows at 150%, build 44b49e9f8, as recorded in
[#3814](https://github.com/hexide-io/HexIDE/issues/3814). After New Horizontal Document Dock, area 0
showed `Probe3784 - Module1 (Code)` with `Language & Debug Servers` behind it; area 1 showed Module2
and held focus. `dump_visual_tree {"match":"TextEditor","window":"ide"}` found both modules' editors
and the Immediate editor, but its note called both Language & Debug Servers and Module1 unselected
and said their contents were not in the tree.

**Workaround.** Trust the returned matches for visible editors. Activating Module1 unnecessarily moves
focus and changes where the next new document opens.

**Fix.** `DocumentDockService.ShownTabs` supplies every document area's selected tab. `MatchNote` excludes
all of them when explaining which open tabs could not be searched. Factory-split regression tests cover
empty and nonempty matches while retaining a genuinely hidden tab. Live verification is for the supervisor:
repeat the call above with that split and confirm only Language & Debug Servers is named as hidden.
