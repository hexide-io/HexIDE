# `interact` leaves a Line drag without a release or an undo step — **CLOSED** (#5789, 2026-11-27)

**Symptom.** On the Debug build of #5759's head (`1a4b07892`), the recorded call was
`interact(target: …/ListItem[Line2], action: "click", value: "80,2 to 120,32", window: "ide")`.
The Line moved, but the reply said its `Image` was removed after the first press and nothing was
released there. `get_undo_state()` reported `canUndo: false`. A headless comparison on main
`689f60a87` found that a Line dragged through Avalonia's mouse input got `Move: Line2` on the undo
stack and ended with `IsDragging` false. The same drag through `UiAutomationDriver.Interact` left
the stack empty and `IsDragging` true. [Issue and measurements](https://github.com/hexide-io/HexIDE/issues/5789#issuecomment-7222364916)

**Workaround.** Drag the Line with the mouse. Its release reaches the designer's resize adorner.

**Fix.** When a press removes its target in an open window, `interact` releases to the pointer
capturer or the control under the release point and names the removed target and release recipient.
Headless tests use the designer and the driver's dispatcher route to verify that both an ordinary
Line drag and a held Line drag followed by `release` end the drag and record one undo step. With
the default grid settings, undo restores all four endpoints. Not live-checked: the tests drive a real
`FormEditView`, with its `ControlItem` and `ResizeAdorner`, through the same driver call the tool makes.
