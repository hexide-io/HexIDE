# A running program's form reports no owner, so which form owns a modal one can't be checked live — **CLOSED** (#4834, 2026-11-19)

**Symptom.** Measured 2026-11-18, a Debug build at #4766's branch, with a program running whose Form2 was shown
modally from Form1. `inspect_element(target: "Window", window: "Form2")` replied with a `frame` of `canResize`,
`windowDecorations`, `canMinimize`, `canMaximize`, `showInTaskbar`, `windowState`, `nativeStyle` and `nativeExStyle`, and
nothing that names an owner. Which window owns a modal form is VB6 behaviour HexIDE reproduces (#4618, #4744): it
decides what stays above what, and what minimizes together.

**Workaround.** None on the surface. The review of #4744 relied on `SeveralFormsTests`, whose headless assertions read
`Window.Owner`, and checked live only what an owner implies: which forms a modal one disables, and which form is
active before it opens.

**Suggested fix.** Add `owner` to the `frame` block `inspect_element` gives a top-level window:
- **Its value:** the owning window's form name and title, as `take_snapshot`'s `window` takes them, or `null`.
- **The native owner too, on Windows:** `GetWindow(hwnd, GW_OWNER)`, described the same way. Avalonia's `Owner` and the
  OS owner can differ. VB6 fidelity is about the OS owner, which a modal from a not-yet-displayed startup form leaves as
  a hidden window (#4744, row l).
- **Pins:** keep the description within its cap. Run the `Category=ToolDescription` tests, and add a case to
  `InspectFrameTests`.

**Fixed.** #4834, in batch 389. The `frame` block `inspect_element` gives a window now carries:
- **`owner`:** Avalonia's `Window.Owner`, as `{ name, title }`, or `null`.
- **`nativeOwner`, on Windows:** `GetWindow(hwnd, GW_OWNER)`, described the same way. A window HexIDE didn't make is
  described as `{ title, className }`, with no `name`. It is `null` when there is no owner.

Each `name` is an address the `window` parameter takes back to that window. `ForegroundWindow.Address` builds it beside
`Pick`, and adds `#n` when several open windows answer to one form name.

**Live check** (hexide-mcp, 2026-11-18, #4834's branch, Debug build on Windows). `Sub Main` showed two instances of
Form1, captioned A and B, then `Form2.Show vbModal, b`:

```text
inspect_element {"target":"Window","window":"Form2"}   → frame.owner       {"name":"Form1#2","title":"B"}
                                                         frame.nativeOwner {"name":"Form1#2","title":"B"}
inspect_element {"target":"Window","window":"Form1#2"} → "window":"B", frame.owner null, frame.nativeOwner null
```

A native owner that isn't one of HexIDE's windows wasn't covered, by the live check or by a test. It needs a foreign
window handle, which the headless suite doesn't have.
