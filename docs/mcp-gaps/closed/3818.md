# Keyboard tools stopped keys before the code window could refuse them — **CLOSED** (#3818, 2026-11-12)

Symptom: on the Windows build recorded in [#3818](https://github.com/hexide-io/HexIDE/issues/3818),
`type_text {"text":"Attribute VB_Description = \"f\"","mode":"keyboard"}` on a new line above
`Option Explicit` in a form reported that key 12 wrote nothing, while the status bar stayed Ready.
`press_key {"key":"X"}` in the form's header likewise refused before delivery. Both calls addressed
the code editor's path from `dump_visual_tree`; the issue did not preserve that path. The automation
pre-check prevented the code window's own text-entering handler and its status message from running.

Workaround: document-mode typing explained the protected region, but could not exercise the window's
reaction to a refused key.

Fix: keyboard typing and key presses deliver the key first. When the attempted edit leaves the code
window's text unchanged, the reply quotes the status-bar message only when that key advanced the
message counter (or says the window gave no message), reports the caret and says the code window
refused it. Keyboard typing stops after that sent key, identifying earlier keys and the unsent remainder. Document-mode typing keeps its pre-check and replies.

Verification: headless Integration tests exercise both tools in a form header, a member's Attribute
run and a hanging Attribute run, asserting unchanged text and caret and the window's status message.
A further test preserves earlier keyboard input while refusing a key in an Attribute line read
from the file. Silent Backspace refusal at the start of the line after that protected run reports
no message rather than quoting Ready; refusal replies say nothing
was written only once. The supervisor verified the original calls live on c13bacba with unchanged protected text and matching status-bar
refusals. Round 3 adds a regression sending refused X and then silent Backspace while X's message
still shows: Backspace reports no message, never the stale reason. Refusal replies contain no double
spaces. Round 4 uses Attribute lines read from the file for these refusals, alongside #3819's coverage
that a member Attribute line stays editable while being typed. The supervisor verified round 3 live;
a live recheck can send X inside an existing member Attribute line, then Backspace at the start of
the following line before the temporary message expires.
