# inspect_element listed every member of an inherited DataContext for a control in a popup — **CLOSED** (#2892, 2026-11-09)

**Symptom (2026-11-02, Windows, #2844's live check, headless first contact).** With the code editor's completion list
open, `inspect_element(target: "Window/…/Custom[Root]/None[TextEditor]/List[PART_ListBox]", window: "ide")` returned
a `CompletionListBox` with `dataContextType: MainViewViewModel` and 100 `dataContextMembers`, about 8–9 KB, with no
`dataContextNote` or `dataContextOwner`. The `items` and `selectionItems` the caller wanted were buried in it. The
snippet's choice list replied the same. The caller called it "noise for a completion list".

#562 made a control that inherits its DataContext report only its owner. That works in the main window's tree, but a
popup's content is in a visual tree of its own. `DataContextOwner` walks visual parents and stops at the popup root,
so no owner is found and the control is treated as owning the context.

**Workaround.** None in the reply. Read `items` and `selectionItems` from the end of it.

**Fixed (#2892).** The walk for where a DataContext is set now crosses from a popup's content to the popup's logical
parent, which is what the content inherits from. That is not always where the popup is placed. A context set inside
the popup still belongs to that content. Guarded by two cases in `LogicallyParentedPopupTests`.
