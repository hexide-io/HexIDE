# A dump with an empty tree doesn't say whether the window holds nothing or the filter left it all out — **CLOSED** (#2725, 2026-10-28)

**Symptom.** Found in #2720's first-contact check. A running program's Form2 has no controls.
`dump_visual_tree(window: "Form2")` returned the root `Window` with `"children":[]` and nothing else. The caller said:
"I couldn't tell whether the form is empty or whether `interactiveOnly` hid its controls, because I didn't retry with
`interactiveOnly: false`." An earlier run had read a TreeView's empty `children` the same way.

**Workaround.** Dump again with `interactiveOnly: false`. On Form2 that shows only a hidden `Window/Menu` node, which is
the empty menu bar every running form has.

**Fixed.**
- **When it applies:** a dump whose tree has no children, and isn't `truncated`, adds a note.
- **The note counts:** it counts the parts one level down that show, leaving out a hidden node such as that menu bar.
- **What it says:** with parts, that `interactiveOnly` left out that many and to pass `interactiveOnly: false`. With none,
  that the window or root holds no controls, and that what is drawn on it, such as a picture, Print output or a list's
  drawn items, shows in `take_snapshot`.
- **Tests:** `EmptyDumpNoteTests`.
