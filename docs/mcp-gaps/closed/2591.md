# No call could see another program's window, so a running program's Shell couldn't be checked — **CLOSED** (#2591, 2026-10-28)

**Symptom (2026-10-28, Windows, hexide-frm, #2573's live check).**
- **The probe and what it needed.** The probe ran `pid = Shell("notepad.exe", 2)`, and the check needed Notepad's window state.
- **No call reached it.** `get_window_state(window: "Notepad")` isn't possible, since `window` names only HexIDE's own windows and a running program's forms. `dump_visual_tree` and `inspect_element` are the same.
- **So `Shell` couldn't be checked,** and nor could anything else that lands in another process's window, such as `AppActivate` and `SendKeys`.

**Workaround, before the fix.** A PowerShell script outside the tools, reading the window by PID with `EnumWindows`, `IsWindowVisible`, `IsIconic` and `IsZoomed`. A first-time caller wouldn't think to write it, and a caller held to the hexide tools can't.

**Fixed (#2591).** `get_process_windows(pid)` describes the top-level windows of a process `Shell` started, and of the processes that one started in turn, by parent ID and creation time, since a launcher can hand off and exit.
- **Each window gives** its title, `state` (Normal, Minimized, Maximized or Hidden), `visible`, `bounds` in screen pixels, `isForeground` and `className`.
- **With no `pid`,** it lists what `Shell` started, with the window style each was given.
- **What it reads, and refuses.** Only processes `Shell` recorded are read. A reused ID is refused by its start time, and nothing is sent to any window.
- **A reply with no window says which case it is:** exited, no window yet, the ID now names another process, or the session has no foreground window.
- **The style comes from `Shell`.** The window style a process was started with is `Shell`'s own argument, so nothing reads the other process's memory.
- **The route is signposted.** `get_window_state`'s unknown-name refusal now names `get_process_windows`.
- **Guarded by** `ProcessWindowsToolTests` and the `ShellTests` recording cases.

**Live (2026-10-28, Windows at 150%, headless `claude -p` from the descriptions alone).** A program ran `Shell("notepad.exe", 6)`, `(…, 4)` and `(…, 0)`.
- **The caller's first move failed and pointed on.** It tried `get_window_state(window: "Untitled - Notepad")`, as hexide-frm had, and the refusal named `get_process_windows`.
- **All three windows read correctly:**
  - `pid` 33160 gave `state: "Minimized"` at -32000, -32000;
  - 37204 gave `Normal` with real bounds;
  - 21832 gave `visible: false`.
  - None had the foreground.
- **Changed after this run,** from the caller's own confusion:
  - a hidden window now reads `state: "Hidden"`, where its show state had read `Normal`;
  - the note says vbHide hid it when that was the style.
