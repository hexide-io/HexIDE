# Templated ComboBox items were named by record debug text — **CLOSED** (#4003, 2026-11-15)

Symptom (Windows Debug, 2026-11-14, reported in [#4003](https://github.com/hexide-io/HexIDE/issues/4003)):
Options → Environment → Language showed English, and
`inspect_element {target: "Window/Custom/Custom/ComboBox[Language]", window: "Options"}`
reported `value: "English"`, `selectionItems: ["English"]`. But
`interact {target: "Window/Custom/Custom/ComboBox[Language]", action: "set_value", value: "German", window: "Options"}`
refused it and listed `LanguageInfo { Id = de, DisplayName = German, Direction = ltr }` among
42 record strings. After
`interact {target: "Window/Custom/Custom/ComboBox[Language]", action: "expand", window: "Options"}`,
`dump_visual_tree {match: "German", window: "Options"}` found nothing; item paths used the record string.

Workaround:
`interact {target: "Window/Custom/Custom/ComboBox[Language]", action: "select", value: "LanguageInfo { Id = de, DisplayName = German, Direction = ltr }", window: "Options"}`
succeeded.

Fix: when an item's peer name is default object/record text, reuse inspection's visible-template-text
rule for selection, refusal lists, tree names and path addressing. Keep the original name as a
selection fallback. Headless tests exercise record templates and path round trips; plain string
ComboBox coverage remains in place.

**Live check** (hexide-mcp, Windows, Debug, 2026-11-15), on the same Language box:
- `set_value "German"` replied "selected 'German'", and the IDE opened its language-change gate in German.
- After `expand`, `dump_visual_tree` with `root` on the box named the realized items by what they show:
  `ComboBoxItem[System default]`, `ComboBoxItem[Arabic]` through `ComboBoxItem[Danish]`.
- The workaround still works: `select` with `LanguageInfo { Id = cs, DisplayName = Czech, Direction = ltr }` replied
  "selected 'Czech'".

`match: "German"` still finds nothing while German's row is out of view. Only the first ten rows of the open list are
realized, and that is #2450's ground, not this gap's. `inspect_element`'s `items` lists every item, and it reads each
row through the same label as the dump (reasoned from the code, not checked live).
