# An action on a running form didn't say what the program printed — **CLOSED** (#2657, 2026-10-28)

**Symptom (2026-10-28, Windows, #2651 and #2652's live checks).**
- **The run and stop replies already said.** Since #2531, the run, step, break and stop replies give the program's `Debug.Print` output in `printed`.
- **The actions on its form didn't.** `interact`, `press_key` and `type_text` replied only with what they did, though each already waits up to 3 s for what the action set off.
- **Two first-contact callers worked around it** from the descriptions alone. Each found the Immediate window with `dump_visual_tree`, read it with `inspect_element` after every click, and diffed it by hand: seven reads in one run. Both had just seen `run_project`'s note naming `printed`, and expected it on the click.

**Fixed (#2657).** On a running program's form, those three replies now give `printed`, with the note's sentence saying how much was printed, or that nothing was.
- **Same tracker, same rule.** They read from the same tracker, with the same rule: "since the run began, or since the last reply that reported its output". So a click's lines arrive with the click, and `stop_project` reports only what came after.
- **Design mode is unchanged.** Actions in design mode, and on the IDE's own windows, reply as before.
- **Guarded by** `ProgramPrintedTests`.

**Still open.** `hover` doesn't wait for the program, so a MouseMove handler's output arrives in the next reply that reports output (#3274).
