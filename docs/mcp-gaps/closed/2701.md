# No tool could create a control array — **CLOSED** (#2701, 2026-11-16)

**Symptom.** #2701 records this call excerpt from #2329's 2026-10-28 first-contact Windows check:
`set_control_property(controlName: "Timer2", property: "Index", value: "0")`
(the issue does not record the `formName` argument). It returned `Property 'Index' not found on VB.Timer`. `set_file_content` also refused the designer-owned
header, so the caller could not build the control-array fixture the check needed.

**Workaround.** Load a previously written `.frm` containing `Index = 0`; no creation route existed in
the tools. Since #1397, the Properties window also offers to create an array when naming one unindexed
control after another of its type; the tool explains the Index-first route, and joining an existing array needs no question.

**Fix.** The Properties window exposes an editable Index for modelled controls. The same setter is
reachable through `set_control_property`: integers 0 through 32767 create or move an element; empty
clears a lone element. Range errors, duplicate indexes and clearing with same-name siblings are refused
without changing the model or saving. Tool replies name the resulting element and its address;
`get_form_controls` and designer dumps use that address. The operation participates in designer undo.

The file-load measurements are recorded in [#2701's supervisor comment](https://github.com/hexide-io/HexIDE/issues/2701)
and measuring PR #4074, destined for the [control-array oracle](../../vb6-fidelity-oracle/control-arrays.md).
The clearing refusal is reasoned from the indexed-first mixed form's measured missing-Index log and
separate unindexed control (Index raises 343), not a claim about VB6's unmeasured IDE prompts or reverse
file order. Existing event procedures are left unchanged, as VB6 leaves them (measured, oracle PR #4358). Since #4205, a new
handler stub for an array element takes `Index As Integer` first.

New and moved indexes use the serializer’s normal property indentation and value columns; untouched
VB6-written arrays retain their bytes. Properties-window refusals give translated instructions without
measurement notes. Duplicate-index and same-name unindexed-control refusals identify the specific case;
automation replies retain the English source note.

**Verification.** Headless tool and Properties-window regressions cover creation, refusal, moving,
clearing, undo and save/load, with exact saved text for new, moved and untouched indexes. The supervisor’s
2026-11-16 Windows check confirmed creation, moving, refusals, clearing/undo and runtime array access
([#2701](https://github.com/hexide-io/HexIDE/issues/2701)). **live check pending (hexide-mcp)** for the
round-2 corrections: save a newly indexed control and a moved loaded element, inspect their property
columns, and compare an untouched VB6-written array byte for byte. Check invalid-value, duplicate-index,
same-name unindexed-control and clear-with-siblings messages in English and another shipped language:
they should give plain instructions, identify the correct collision case and show no measurement notes.
Automation refusals should still name the conflicting control and retain their English source note.
