# Tool pane title expand reports success without a usable menu — **CLOSED** (#4155, 2026-11-16)

**Symptom.** On Windows, `interact(target: "Window/Custom[MainView]/Pane[DockControl]/Pane[Root dock]/List[PART_ItemsControl]/List[#0]/TitleBar[Tool.immediate]", action: "expand", window: "ide")`
replied `expanded 'Immediate'` without showing the pane menu. An invisible light-dismiss overlay
swallowed the next pointer press. The [issue](https://github.com/hexide-io/HexIDE/issues/4155) records
two live reproductions. Headlessly, the peer branch uses
`Dock.Avalonia.Automation.Peers.ToolChromeControlAutomationPeer` as both peer and expand/collapse
provider. Its state reads `Expanded`; the shared `ToolFlyout` reports open on the `ToolChromeControl`,
with a `MenuFlyoutPresenter` child and one `LightDismissOverlayLayer`.

**Workaround.** Press Escape after the misleading expansion, then expand the title bar's
`None[PART_Border]` child, or right-click its title.

**Fix.** Title-bar expand and collapse now use the template's unique `PART_Border` holding its
`ToolFlyout`. The existing flyout route verifies the popup state and the reply names the pane menu
and its border. An unavailable or ambiguous part refuses with the child to target. A failed new
opening hides the flyout before returning. The headless regression uses the real Immediate view model
in a deterministic docked layout inside `MainView`, checks all three menu items in the dump,
collapse and repeated collapse, the next right pointer click, and the original border expansion route.
Live Windows verification remains with the supervising session.

**Test-sequence caveat.** A separate headless probe right-clicked the title immediately after opening
and dumping the now-visible menu, before collapse. Its reply still correctly named
`LightDismissOverlayLayer` as covering the title: an open menu intentionally owns that layer. The
regression checks the next pointer click after collapse. Removing or bypassing a visible menu's
light-dismiss layer to meet the issue comment's literal “straight afterwards” test would change real
pointer routing; that instruction needs supervisor review.
