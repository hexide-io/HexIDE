# Ticking text gets a path that expires a second later — **CLOSED** (#3028, 2026-11-04)

**Symptom (Windows, 2026-11-04).** In the Language Servers card, the call
`dump_visual_tree(window: "ide", interactiveOnly: false, match: "for 1 m", maxDepth: 12)`
matched `<Card>/Text[for 1 m 31 s]`. Here `<Card>` expands to
`Window/Custom[MainView]/Pane[DockControl]/Pane[Root dock]/List[PART_ItemsControl]/List[#0]/Pane[#0]/Custom/ScrollViewer/List[#0]/List`.
`inspect_element(target: "<Card>/Text[for 1 m 39 s]", window: "ide")` and
`inspect_element(target: "<Card>/Text[for 1 m 40 s]", window: "ide")` returned
`no child matching`. Under `bg`, the same happened with
`inspect_element(target: "<Card>/Text[за 2 мин 20 сек]", window: "ide")` and
`inspect_element(target: "<Card>/Text[за 2 мин 21 сек]", window: "ide")`.
Only a guess at the current second, `Text[for 1 m 38 s]`, succeeded.
See [the original measurements](https://github.com/hexide-io/HexIDE/issues/3028).

**Workaround.** Address the text by its same-type sibling index (`Text[#n]`) rather than guessing its next value.

**Fix.** The emitter omits automation-label candidates for TextBlock (including SelectableTextBlock)
Text data bindings: compiled bindings, reflection bindings and MultiBinding. AutomationId and x:Name
still win; otherwise the existing bare-type or same-type index fallback applies. Literal text,
resource references, TemplateBinding and other control types keep their existing paths. Current labels
still resolve. A missing typed label beside data-bound text explains that it changes, is addressed by
position, and asks for `dump_visual_tree` again with `interactiveOnly: false`. Tool descriptions are unchanged.

**Verification.** Headless integration tests cover changing values and the binding/resource distinction.
Live check passed (hexide-mcp, 2026-11-04, Windows): the Language Servers age dumped as `<Card>/Text[#13]`
("for 8 s"), and the same path read "for 10 s" two seconds later. A stale `Text[for 8 s]` got the new
guidance. `Text[Id]` and literal and resource texts kept their labels, and a running form's Label stayed
`Window/Text[Label1]`.
