# Form inspection hid Bring to Front and Send to Back

**Symptom.** On 2026-11-09, on PR #3537's build, `get_form_controls(formName: "Form1")`
returned Command1, Command2 both before and after selecting Command1 and calling
`invoke_menu_item(path: "Format/Order/Bring to Front")`. The children of `List[ControlsContainer]`
in `dump_visual_tree` changed to Command2, Command1, the snapshot drew Command1 over Command2,
and `get_undo_state` reported `Bring to Front: Command1`. The inspection used `AllComponents`,
which does not follow live stacking changes. Measurements and the decision are in
[issue #3538](https://github.com/hexide-io/HexIDE/issues/3538).

**Workaround.** Read the children of `List[ControlsContainer]` from `dump_visual_tree`.

**Fix.** Inspection lists each container's children bottom first and reports `zOrder`, starting at
zero. Compare it only among rows with the same `container`; an absent field means the form. Forms and menus
have no `zOrder`. Open designers supply live stacking; closed designers supply the corresponding
model order. Carried controls participate too. Named inspection preserves the full list's position.
The tool description explains this contract.

The other `AllComponents` readers in `HexIdeTools.cs` locate a control for property assignment or
movement by name; neither returns an ordered control list, so neither needs changing. The stacking
commands and save path are unchanged. Regression coverage is in `FormControlsSummaryTests` and
`CarriedControlsDescriptionTests`.
