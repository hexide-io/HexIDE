# Popup bounds were measured from the popup's corner — **CLOSED** (#3149, 2026-11-05)

**Symptom.** The Windows measurement in [#3149](https://github.com/hexide-io/HexIDE/issues/3149)
used `inspect_element {"target":"…/Pane[Watches]/Custom/Tree/ContextMenu","window":"ide"}`
and got `[0, 0, 142, 54.67]`. Inspecting its `ScrollViewer/MenuItem[Edit Watch...]` gave
`[5.33, 3.33, 131.33, 24]`, although the menu opened at approximately (384.3, 550.7) window DIPs.
The snapshot's window-relative mapping therefore placed the item near the image's corner.

**Workaround.** The reporter read the menu's screen rectangle externally and subtracted the window's
client origin. Those measurements belong to the issue; they were not repeated in this run.

**Fix.** Translate the popup peer's rectangle through its top-level's screen coordinates into the
selected window's client coordinates. If that cannot be done, leave the bounds unavailable with
`boundingRectNote`.
`dump_visual_tree` was checked: its nodes have no bounds field, so there is no second rectangle to fix.
Headless tests supply the native popup host missing from Avalonia's headless backend, open a
ContextMenu at a known screen origin and inspect both the menu and its item, including at 150% window
scaling. All five cases fail with the old peer-relative read restored and pass with the correction.
Live Windows verification remains for the supervisor: inspect the watch menu
and item, map their bounds with snapshot units, and check that both land on the drawn menu at 150%.
