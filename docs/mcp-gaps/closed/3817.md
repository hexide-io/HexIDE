# A zero-match note omits label from the fields searched — **CLOSED** (#3817, 2026-11-12)

**Symptom.** Measured on Windows at 150%, build f934745f, with Immediate floated, as recorded in
[#3817](https://github.com/hexide-io/HexIDE/issues/3817).
`dump_visual_tree {"window":"Immediate","match":"IRootDock","interactiveOnly":false}` answered
`Nothing matches 'IRootDock'.` and listed Name, AutomationId, ClassName, ControlType, typeNameAsName
and the DataContext type as searched, omitting label.
`dump_visual_tree {"window":"Immediate","match":"Dock command bars","interactiveOnly":false}`
answered `1 node matches 'Dock command bars'.` with
`Window/Pane[Dock host]/ToolBar[PART_CommandBarHost]`, whose name was `PART_CommandBarHost` and whose
label alone held `Dock command bars`.

**Workaround.** A second search for a known label confirms labels are covered; an empty reply alone
incorrectly suggests they are not.

**Fix.** `MatchNote` now includes `label` in the parameter's order. A regression test derives the searched
fields from `UiAutomationDriver`'s matching predicate and compares the note's complete list. Live
verification is for the supervisor: repeat both calls above and confirm the zero-match note includes
`label` while the label search still returns the command bar host.
