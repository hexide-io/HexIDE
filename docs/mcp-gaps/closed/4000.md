# Oversized `set_window_state` clips bottom-docked panes — **CLOSED** (#4000, 2026-11-14)

Symptom: measured in [#4000](https://github.com/hexide-io/HexIDE/issues/4000) on main 635a2101c,
Windows at 150% scale on a 1920×1080 screen, starting Maximized with a project, code window and
Tools/Diagnostics open. `set_window_state {"window":"ide","state":"Normal","x":0,"y":0,"width":1400,"height":900}`
replied with 1282×700, but `inspect_element` on `…/TitleBar[Diagnostics]` returned
`"boundingRect":[0,688,1075.3,190]`, extending to y 878. `take_snapshot` showed only the status bar
at the bottom. `set_window_state {"window":"ide","state":"Maximized"}` brought the pane back.
A Win32 restore and move to the same reported client size laid out correctly.

Workaround: ask for a size that fits the working area.
`set_window_state {"window":"ide","state":"Normal","x":0,"y":0,"width":1100,"height":620}`
was measured to lay Diagnostics out correctly at `[0,472,844,126]`.

Round 1 (`1517e86a`) reconciled explicit dimensions after platform confirmation. The Windows live
check recorded in #4000 still found Diagnostics at `[86.7,752.7,1077.3,125.3]`, although MainView
was `[0,0,1282.7,700]` and DockControl `[0,50.7,1282.7,627.3]`. A later root remeasure did not repair
the dock's layout after it had seen the oversized request. The fitting 1100×620 control remained correct.

Fix: clamp requested client dimensions before assigning layout properties, using the working area
of the screen at the requested position and allowing for `FrameSize` minus `ClientSize`. Retain the
post-confirmation reconciliation for any further native adjustment. The reply explains requested and
allowed sizes using the same one-decimal formatting as its geometry; rounding within one device pixel
produces no note. Headless tests use delayed native clamping, several stacked bottom panes, a fitting
odd size at 150%, and a later user resize.

**Live check** (hexide-mcp, Windows at 150%, 1920x1080, 2026-11-14), with Immediate, Locals, Watches and
Diagnostics docked at the bottom. Round 1, which reconciled the size after applying it, still left Diagnostics at
y 752.7 to 878 in a 700-high client area: the dock kept its layout from the brief arrange at the requested size.
Round 2 clamps first. From Maximized, `Normal` at 1400x900 replied 1265.3x634.7, with the note giving the requested
and allowed sizes, and Diagnostics' title bar was at y 528.7 to 612.7, inside the client area. `Normal` at
845x601, a size that fits, gave 845.3x601.3 with no note, and Diagnostics was inside. A resize by hand was not
checked, since it would mean moving the mouse.
