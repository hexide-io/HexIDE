# Archive entry tabs omit their identity — **CLOSED** (#3929, 2026-11-14)

**Symptom.** Measured on Windows at f4cd930e in
[#3929](https://github.com/hexide-io/HexIDE/issues/3929): after
`open_file("/Sources/Entry.twin", project: <container>)`, `get_document_tabs()` reported
`{"title":"Entry.twin","type":"code","isActive":true,"area":0}`, omitting the container and entry
paths that `open_file` returned. Two archives holding the same entry path could not be distinguished.

**Workaround.** Address the tab by its title, which is ambiguous when two archives hold entries
with the same name.

**Fix.** Tab info now uses the entry's container identity and the same `ArchiveToolPaths.PathOf`
helper as `open_file`, reports `type: archive` for a read-only archive entry, and continues to omit
`isModified`. Activation and closing accept `archive` as a type filter. The tool descriptions name
the new type. The bounded `open_file` miss listing was already fixed in #3931.

**Verification.** Headless regressions cover identity, duplicate entry paths, and activation and
closing with the archive type. hexide-mcp's live check on Windows (2026-11-14), with
`impexp.twinproj` open: after `open_file("/Sources/Entry.twin")`, `get_document_tabs` listed the tab as
`type: archive` with the same `project` (the container path) and `document` (`/Sources/Entry.twin`) as
`open_file`'s reply, and no `isModified`. `activate_document_tab` and `close_document_tab` with
`title: "Entry.twin", type: "archive"` both succeeded. The two-archive case is covered by the headless test only.
