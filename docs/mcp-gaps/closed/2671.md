# A Make from the menu replied only "Invoked", so no caller could tell whether a program was made — **CLOSED** (#2671, 2026-10-28)

**Symptom (2026-10-28, Windows, #2659's live check).** File → Make, reached with `invoke_menu_item` and its save dialog answered by `answer_next_file_dialog`, replied `{"success":true,"note":"Invoked 'Make Project1...'."}`.
- **It said the same however Make ended:** a program made, a Make that failed, or one that never started.
- **No path, size or reason came back.** The dialog answer's own note says "Nothing has been created there", so nothing in the replies said a file existed.
- **Both first-contact callers that made a program ended unsure** and asked for someone with file system access to look. Both programs had been made.
- **A Debug build has no standalone runner until it is published,** so a Make failing for that reason read the same as a success.

**Fixed (#2671).** Make reports what it ended with to `MakeOutcomes`, and `invoke_menu_item` waits for that when its item started a Make.
- **When a program was made,** the note names it and the project zipped beside it, with their sizes. It says the program is the standalone runner, which carries .NET, and whether it wrote over a file already there. That is Make's own observation, so an old program at the path can't pass for a new one.
- **When nothing was written,** the note says why: the missing runner and the folder it was looked for in, a cancelled dialog, a form or module HexIDE can't write as it was read, a character the code page can't hold, or the exception. It also says whether a message box saying so is open. The reason is reported before that box opens, since Make waits on it.
- **A Make waiting at a save dialog** that no answer was armed for is reported as that after a second, rather than at the 60 s limit. The dialog is the operating system's, which no tool reaches.
- **`success` stays true** when Make wrote nothing: the item was invoked, and the IDE did what Make does. The note's first words say whether a program was made.
- **Guarded by** `MakeOutcomesTests`.

**Live (2026-10-28, Windows, headless `claude -p` from the descriptions alone).**
- **No runner published:** the note named the runner, the folder and the answered path, and said a box was open. The caller answered the box with `interact`.
- **Nothing armed:** Make, run again, was reported as waiting at its save dialog.
- **With the runner published:** two Makes to one path were reported as made, with 110,851,116 and 575 bytes, which a directory listing confirmed. The second said it wrote over the first.
- **Changed after these runs, from the callers' own confusion:**
  - the runner reason names the path the dialog gave, since one caller couldn't tell whether its armed answer was used;
  - the success note says what the two files are.
