# SSTab pages require reading a picture — **CLOSED** (#2694, 2026-11-13)

Symptom: #2694 records that `dump_visual_tree(root: <SSTab designer item>, interactiveOnly: false)`
showed an Image rather than named tab headers. `get_form_controls(formName: "Form1")` reported
`container: "SSTab1"` for a child but no page membership.

Workaround: read a snapshot and click a header, as in
`interact(target: <ListItem[SSTab1]>, action: "click", value: "150,10")`.

Suggested fix: expose the selected page through the existing property tool and report child membership.

Source audit before the fix: `set_control_property(formName: "Form1", controlName: "SSTab1",
property: "Tab", value: "2")` refused with `Property 'Tab' not found on TabDlg.SSTab`.
`get_form_controls(formName: "Form1", controlName: "SSTab1")` included a saved `Tab` only as a
read-only raw property when present; an omitted default had no row.

Fix: inspection now reports the SSTab's selected `Tab` and `Tabs`, and each child's zero-based `tab`
from page metadata, with the designer open or closed. Setting `Tab` reuses designer page bookkeeping,
including hidden Left offsets, and names the valid range on refusal. `zOrder` remains per SSTab,
across all tabs, matching the designer's single child draw-order list. No new tool was added.
Headless tests cover these calls; live verification is reserved for the supervising IDE session:
switch between pages with children, confirm captions and visible children redraw, and read membership
before and after closing the designer.

The existing page positions and saved lists follow the [SSTab measurements](../../vb6-fidelity-oracle/in-box-controls-the-sstab.md); this change adds no VB6 measurements.
