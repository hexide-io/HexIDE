# The run and debug tools misreported a project no run engine runs — **CLOSED** (#3514, 2026-11-09)

**Symptom (2026-11-09, Windows, found while taking the #3411 seam item).** With a project an add-in read as the startup project and nothing running:

- `run_project()` replied `"Project is already running"`, which was false.
- `step_into()`, `step_over()` and `step_out()` replied `"No project to step — load a project first"`, and `run_to_cursor(module: "Module1", line: 2)` replied `"No project to run — load a project first"`. A project was loaded.
- `get_locals()`, `get_call_stack()` and `evaluate(expression: "1")` said to `set_breakpoints` and then `run_project`, which would refuse.
- `get_debug_state()`, `get_watches()` and `get_last_runtime_error()` read as though the project just hadn't run yet.

The same line of `run_project` also said "already running" while an archive had the focus.

**Workaround.** Knowing to look in the Run menu for Start Once With.

**Fixed (#3514, part of #3411).** The tools ask the runner, whose `StartupWithNoEngine` answers from `IRunEngine.Runs`, so the rule stays with the engine and a build with no engine is reported the same way. Each reply says no run engine runs the project and what can: each launch add-ins offer for it, as its `invoke_menu_item` path, or else that no add-in offers one and how to run it under a debug adapter. `get_debug_state`, `get_watches`, `add_watch` and `get_last_runtime_error` say so in `note`. With an archive focused, `run_project` now says the project can't be started now and how to move the focus.

**Still as it was:** `invoke_menu_item` on Run > Start, and F5 through `press_key`, report a disabled item as they do for any disabled item.
