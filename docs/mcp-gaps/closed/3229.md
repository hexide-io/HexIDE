# `run_project` loses output printed by a fast `Form_Load` — **CLOSED** (#3229, 2026-11-06)

**Symptom.** With a new project's `Form_Load` containing `Debug.Print "load"`, repeated
`run_project {}` then `stop_project {}` calls sometimes both reported that nothing was printed.
The Immediate window still held `load`. The Windows measurement in
[#3229](https://github.com/hexide-io/HexIDE/issues/3229) found five missing replies in eight runs.

**Workaround.** Read the Immediate window using `inspect_element` with `window: "ide"` and the
editor path discovered by `dump_visual_tree(window: "ide", interactiveOnly: false)`.

**Suggested fix.** Clear the output buffer when the runner claims the run, before execution,
rather than when `IsRunning` becomes true after the startup form has begun loading.

**Fix.** The runner raises `RunStarting` when it claims `RunningProject`, alongside `RunScope.Begin`.
`ProgramPrinted` follows that event; becoming active or ending no longer discards output. External
sessions raise the same event when their tracking begins. Headless `run_project` tests reproduce the
missing line with `TimeSliceMs = null` before the fix, and pass with both null and -1 after it. They also
check that the stop reply does not repeat reported output and that a second silent run stays silent.
Live verification remains for the supervising session: repeat the issue's eight run/stop pairs and
check each run reports `printed: "load\n"`, with no repeated output on stop.
