# Refused writes leave recovery copies — **CLOSED** (#3902, 2026-11-13)

**Symptom.** Measured on Windows in [#3902](https://github.com/hexide-io/HexIDE/issues/3902): after
`set_control_property(formName: "Form2", controlName: "SSTab1", property: "Tab", value: "1")`, refused
calls with `value: "3"` and `value: "x"`, and
`set_control_property(formName: "Form2", controlName: "Command9", property: "Height", value: "abc")`
left copies identical to the current file. Five refusals could evict a useful recovery copy.
An unsaveable-form call with `controlName: "Command9", property: "Caption", value: "Probe"` also left
a copy and did not explain that the value was set in the IDE. The comment does not record that call's
`formName`.

**Workaround.** Keep a separate copy of the desired recovery file before further write calls.

**Fix.** Scope recovery copies to the write attempt and prune only after a write. Refusals and exceptions
that write nothing discard their copies. The unsaveable-form property reply explicitly reports the
in-memory edit and unchanged disk file. Successful replies and the five-copy limit are unchanged.
Headless tests cover the three writers. hexide-mcp's live check confirmed it on Windows: refusals after a
successful write left only that write's copy, the unsaveable form's Caption reply says it is set in the IDE,
and refused `add_control` and `set_file_content` calls left no copy.
