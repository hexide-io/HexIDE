# get_form_controls leaves out the controls the designer carries view-only, and doesn't say so — **CLOSED** (#2882, 2026-11-06)

**Symptom (2026-11-02, Windows, #2855's live check, headless first contact).** The project was
`corpus/inbox-controls/pending/imagecombo`, whose Form1 holds eight ImageCombos and an ImageList.
- `get_form_controls(formName: "Form1")` returned only `Form1` and `ImageList1`.
- `dump_visual_tree(window: "ide", match: "Unmodelled", interactiveOnly: false)` returned 8 nodes, ImageCombo1 to
  ImageCombo8, each a `ClassicBorderDecorator` with `UnmodelledControlViewModel`. The snapshot showed eight labelled
  boxes.
- The caller reported that the tool "omits the eight unmodelled ImageCombos even though they sit on the form".
- `pending/monthview` did the same: `Form1` alone, against nine MonthView boxes in the tree.

A carried control is never a `ComponentInstance`, and the tool reads only those. The reply doesn't say it left anything
out, so a caller can't tell a control that isn't there from one HexIDE draws but doesn't model. Any form holding a
third-party OCX shows the same.

**Workaround.** `dump_visual_tree` with `match: "Unmodelled"` and `interactiveOnly: false`. A caller who doesn't know
that view-model's name won't think to look.

**Suggested fix.** #2882:
- list carried controls as rows marked as carried, with name, type, position and size;
- answer `controlName` for one with that row, not "no control named";
- at the least, a `note` counting what was left out.

**Fixed.** `get_form_controls` includes preserved control blocks alongside modelled components, with name,
block type, container-relative pixel position and size, `carried: true` and a note explaining that HexIDE draws
but does not model them, so they cannot be moved, sized or set. `controlName` finds those rows without regard
to case. The same block reader supplies the designer boxes, including in-box controls carried view-only.

**Verification.** Headless tool tests cover listing and named lookup on form-level and container-level blocks.
Live verification is left to the supervising session: on imagecombo's Form1, check all eight ImageCombo rows
alongside Form1 and ImageList1, then request `controlName: "ImageCombo1"` and check its row and read-only note.
