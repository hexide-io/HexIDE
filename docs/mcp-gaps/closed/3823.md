# A headerless module's saved copy stays a line short — **CLOSED** (#3823, 2026-11-12)

**Symptom.** With `Module=NoName; Plain.bas` and a three-line function in `Plain.bas` with no name attribute, `get_file_content("NoName")` reported the following during the live check recorded in [#3823](https://github.com/hexide-io/HexIDE/issues/3823):

| When | `get_file_content("NoName")` | `hasUnsavedChanges` | `Plain.bas` on disk |
|---|---|---|---|
| Opened | the 3 lines, no name line | false | the 3 lines |
| After Save Project (File > Save Probe) | the 3 lines, no name line | false | `Attribute VB_Name = "NoName"`, then the 3 lines |
| Reopened | the name line, then the 3 lines | false | unchanged |

**Workaround.** Reopen the project after saving to make its copy agree with disk.

**Fix.** The save passes the written module header through the existing header refresher, recording it on the model, refreshing an open editor and moving marks. `get_file_content` describes unsaved edits rather than promising that saving cannot normalise an unedited file. The latest issue comment deliberately leaves freshly opened modules clean: VB6's dirty state for this case is unmeasured. No other tool description made the same promise.

**Verification.** `SaveRecordsTheHeaderTests.AHeaderlessModulesSavedCopyIncludesTheNameLine` covers loaded modules with and without an open editor, the saved text, caret and marks.
