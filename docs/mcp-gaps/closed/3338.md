# A tab tool needed a tab's exact title, so a document's name passed as `title` was refused — **CLOSED** (#3338, 2026-11-08)

**Symptom.** A first-time caller passed "Var1" to `activate_document_tab` for the tab "Probe2 - Var1 (Code)", as the
supervisor relayed it on 2026-11-08, and was refused with `No document tab with title 'Var1'. Open tabs: …`. The run
didn't record the exact call. A `title` was compared with each tab's whole title, and "Var1" is only the document's
name, which `get_project_info` lists and `open_file` takes. The description did say to pass `name` for a document. A
caller reaching for `title` on a tab tool paid a refusal and a second call to find that out.

**Workaround.** Pass `name` (with `project` and `type` where needed), or copy the title from `get_document_tabs`.

**Fixed (#3338).** Both tab tools try a title that matches no tab as a document name among the open tabs.
- **One tab shows that document:** it is acted on, and the note says the title was taken as a document name, and
  that `name` is the parameter for a document.
- **Several tabs show it:** the call is refused, naming each tab and saying whether `project` or `type` picks one.
- **None does:** the refusal lists the open tabs, as before.
- **Guarded by** four cases in `ImplicitDocumentNamingTests`, each run for both tools.
