# A write refusal suggests a file-dialog answer that cannot save a folderless project

**Symptom.** Measured on Windows on 2026-11-16 while live-checking #4180, in an IDE
started with `--newproject-unsaved` ([#4335](https://github.com/hexide-io/HexIDE/issues/4335)):

1. `add_control {formName: "Form1", type: "CommandButton", x: 16, y: 16, width: 81, height: 33}`
   refused because Form1 had no file, advising `answer_next_file_dialog`.
2. `answer_next_file_dialog {path: "<a scratch folder>\\Form1.frm"}` returned pending 1.
3. The same `add_control` refused because the project had no folder, saying
   “Save Project in the IDE first”; the answer remained pending.

**Workaround.** Start with `clear_file_dialog_answers` if an answer is already pending.
In an existing destination directory, arm one `answer_next_file_dialog {path: "<absolute path>"}`
for each unsaved form, then each unsaved module, then the project file, in project order.
For the default unsaved project, that is `Form1.frm`, then `Project1.vbp` in the same directory.
Call `invoke_menu_item {path: "File/Save Project1"}`, then retry the write tool.
The menu includes the project or group name and is localized; use `dump_visual_tree`
to read the actual path for another name or language. A group may also need a group-file answer.
Arming a destination for the document alone cannot establish the project's folder.

**Fix.** Every write-tool picker refusal now checks the project's folder and shares the
same route advice with the armed-destination safety refusal. Projects with a folder keep
the existing document-picker advice. The refusal neither arms nor consumes an answer.
`UnsavedProjectWriteTests` follows the production unsaved-project creation and menu-save
route headlessly, checks the files and answer queue, and then adds a control successfully.
Windows live verification remains the supervising session's check.
