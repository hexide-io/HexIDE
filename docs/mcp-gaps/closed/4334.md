# Selecting a closed dropdown requires an extra call — **CLOSED** (#4334, 2026-11-16)

Symptom, measured on Windows while checking #4180: the Properties object list refused this call while closed:

```json
{"target":"Window/Custom[MainView]/Pane[DockControl]/Pane[Root dock]/List[PART_ItemsControl]/List[#1]/TitleBar[Tool.properties]/Pane[Tool.properties]/Custom/ComboBox[ObjectSelector]","action":"select","value":"Command1","window":"ide"}
```

The reply was `{"success":false,"mechanism":"peer","error":"'ObjectSelector' has no selectable items realized — 'expand' it first, then select"}`.

Workaround: call `interact` with the same target and window, `action: "expand"`, then repeat the selection.

Fix: `SelectComboItem` opens a closed ComboBox through its expand provider, uses the existing item matching and selection, and closes it again, including on a miss. Success says the list was opened first; a miss lists available items. Disabled and hidden targets are still refused before opening. Headless regression tests cover these paths and the existing open path. The supervisor's live check remains to confirm the Properties object list on Windows; no live verification is claimed here.
