# New-project writes sounded like a completed save — **CLOSED** (#2707, 2026-11-06)

**Symptom.** On #2691's head, `set_control_property(Form1, Command1, Caption, "Go")` replied
"the file is saved", while `get_file_content(Form1)` reported `hasUnsavedChanges: true` and
`get_document_tabs()` reported `isModified: true`. The measurements are in
[#2707](https://github.com/hexide-io/HexIDE/issues/2707). The three write descriptions also made a new
project's form sound pathless, and a temporary project path did not explain whether it was chosen.

**Workaround.** Read the unsaved flags and use Save Project to choose the project's home.

**Fix.** Successful property, control and source writes now name the file or temporary working copy.
Working-copy replies explain that Save Project asks where it belongs. Descriptions distinguish the
new project's temporary working copy, written without a picker, from a pathless document that needs
an armed picker. Project info's existing optional note names projects with no chosen home, including
in groups. No parameters or reply fields were added, so schema required arrays are unchanged.

**Verification.** Headless regression tests and tool-description guards cover the change. A live
first-contact check remains for the supervising session: start with `--newproject`, add a button,
change its Caption, replace the form's code, and compare each reply with the unsaved flags. Save
Project should ask for a destination; after saving there, write replies should identify a file.
