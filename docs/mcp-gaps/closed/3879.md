# Paste and Delete Line replies disagree with the code window — **CLOSED** (#3879, 2026-11-13)

Symptom: [#3879](https://github.com/hexide-io/HexIDE/issues/3879) measured
`press_key(target: <code window TextArea path>, key: "V", modifiers: "Ctrl")`
with selection offsets 73–105 and clipboard `ong`: the reply refused the mixed
selection while Edit/Paste replaced its editable portion. The same target with
`key: "Y", modifiers: "Ctrl"` on a locked Attribute line reported a press without
explaining that nothing was written.

Workaround: `invoke_menu_item("Edit/Paste")` replaced only editable text.

Fix: observe partial selections for paste, cut and Tab/Shift+Tab as well as
Delete/Back, and recognise the IDE keymap's Delete Line gesture when judging an
unchanged document after delivery. Ctrl+Shift+V has no binding. No editor-side
Delete Line or Redo behaviour is changed (#3880).

Verification: headless TypeKeysTests exercise the actual code window and replies: 61 passed,
with all six new cases failing against the original driver. Full Integration passed
3,559 with four existing #3869 skips; its xunit report records no errors.
A live Windows check remains for the supervisor: repeat the measured selection,
confirm the declaration is repaired, the Attribute line is unchanged and the reply
names what stayed; press Delete Line inside that Attribute line and confirm a
refusal with unchanged text. No live check was performed in this run.
