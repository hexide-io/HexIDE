# shutdown_ide's reply doesn't say it discarded unsaved edits, and with force false says to poll /health while a save prompt waits — **CLOSED** (#4079, 2026-11-16)

**Symptom.** Measured 2026-11-16 on Windows, with a Debug build of main `80cd5151a`. The IDE was a `--newproject` one,
with Form1's designer tab reading `isModified: true` in `get_document_tabs`.
- `shutdown_ide {}` replied `{"requested":true,"projectStopped":false,"dialogsClosed":0,"note":"Shutdown requested. Poll
  /health until it stops answering to confirm the process exited."}`. The IDE exited and Form1's change was discarded,
  but the reply doesn't say so.
- `shutdown_ide {"force": false}` gave the same reply, word for word. But the IDE didn't exit: a save-changes dialog,
  listing Project1 and Form1, opened and waited. A caller who follows the note polls `/health` for ever.

**Workaround.** Before the default `force`, read `get_document_tabs` for `isModified`. After `force: false`, run
`dump_visual_tree {window: "auto"}`. The prompt is the auto window: `interact` on `Window/Custom/Button[Cancel]` keeps the
IDE and its edits, and on `Window/Custom/Button[No]` closes it.

**Fix.** The reply lists the unsaved project, forms and modules, gathered on the UI thread after the editors' buffers are
applied and before shutdown begins, exactly as the close prompt builds its own list. With `force` true it returns
`discardedDocuments`, empty when nothing was modified, and says what it discarded. With `force` false and unsaved work, it
names the documents and points to the waiting prompt instead of `/health`. The main window still closes only after the
reply has gone (#644).

**Checked live** on 2026-11-16, at the fix's head, on Windows:
- `force` true on a dirty `--newproject` listed `Project1` and `Project1/Form1`;
- on a saved, untouched project it said it discarded nothing;
- `force: false` with Module1 edited named the prompt; `dump_visual_tree {window: "auto"}` found it; Cancel kept the
  IDE running with the edit;
- the default `force` then listed `Project1/Module1`, and the edit never reached the file.

The full table is in PR #4183.
