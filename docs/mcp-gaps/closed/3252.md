# `get_call_stack` returns every frame, so at a deep recursion its reply is millions of characters — **CLOSED** (#3252, 2026-11-06)

**Symptom.** Measured on 2026-11-06 with #3250's Debug build at fe5c69883, whose 64 MiB UI-thread stack lets a
recursion go deep under F5. A module's `Runaway(ByVal n As Long)` called `Runaway(n + 1)`, and `Form_Load` called
`Runaway(1)`. After `run_project {}` and `break_program {}`, `get_call_stack {}`, which takes no arguments, replied
with one line of JSON:

| Frames | Reply size |
|---|---|
| 157,885 | 7,578,576 characters |
| 126,654 | 6,079,488 characters |
| 113,153 | 5,431,440 characters |

Every frame but the first and last was the same `{"proc":"Runaway","module":"Module1","line":29}`. Claude Code refused
each reply as exceeding its maximum allowed tokens and saved it to a file, so the model never saw the answer. The
reply at 126,654 frames also raised the IDE's commit from 3,012 MB to 3,359 MB.

**Workaround.** Keep a depth counter in a module-level variable, and read it with `evaluate` while paused. Where the
client saves an oversized reply to a file, count its `"proc"` rows with shell tools.

**Suggested fix.** Collapse consecutive identical frames into one row with a count. Bound the reply with an optional
`maxFrames`, and report `totalFrames` and a note saying how many rows were left out. #3252 has the details and a
headless test.

**Fix.** `get_call_stack` collapses consecutive frames with the same procedure, module and line into a row
with `count` (including 1 for a single frame). `totalFrames` reports the full depth before collapsing.
Optional `maxFrames` bounds the collapsed rows, deepest first, defaulting to 200; nonpositive limits are
refused. A truncated reply says how many rows were omitted and what `maxFrames` includes them all.
The tool description explains both summarisation and the limit.

**Verification.** Headless `CallStackReplyTests` pauses a real interpreter recursion at 3,000 calls and
checks the deepest frame, the 2,999 repeated callers and the outermost `Main`, with `totalFrames: 3001`.
All eight new cases fail against the previous tool and pass with the fix, including row limits and the
generated schema's optional parameter. Live verification remains for
the supervising session: break a deep recursion, call `get_call_stack {}`, then request a small
`maxFrames` and follow its note to expand the reply.
