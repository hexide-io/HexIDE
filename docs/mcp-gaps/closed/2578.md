# `open_file` put the caret in a form's header without saying so — **CLOSED** (#2578, 2026-10-29)

**Symptom (2026-10-28).** A first-contact caller asked to type at the end of a new form's code counted the header by
hand and called `open_file(name: "Form1", line: 16, column: 1)`. The reply said only "The caret is at line 16, column
1: offset 420". The next `type_text` was refused, because offset 420 is in the header, and that refusal was the first
the caller heard of it.

**Workaround.** Move the caret to the offset the refusal names, then type again.

**Fixed.**
- **The note:** when the caret `open_file` places is in a part only the IDE changes, the note says so, names the
  part (the file's header, or the Attribute lines describing a member), and gives the nearest place that can be
  edited, by line, column and offset.
- **One check for both tools:** it asks what `type_text`'s own check asks, an insertion at the caret, so the two can't
  disagree.
- **A read-only window:** a window that refuses typing everywhere says so.
- **Tests:** `CaretPlacementTests`.
- **Live check:** a first-contact run sent to line 16 read "The nearest place that can be edited is line 18, column 1:
  offset 485", moved there, and typed with no refusal.
