# A form instance whose title is its shared form name cannot be addressed — **CLOSED** (#4659, 2026-11-18)

**Symptom.** With two instances of Form1 open, the default titled "Form1" and a second titled
"second", focusing "second" left no window value that reached the default instance. Reported by
hexide-frm in [#4659](https://github.com/hexide-io/HexIDE/issues/4659), 2026-11-18:

```text
interact {"target":"Window","action":"click","value":"60,60","window":"Form1"}
→ 2 open windows answer to 'Form1', as two instances of one form do: Form1 ("Form1"), Form1 ("second"). "auto" reaches one of them, Form1 ("second"), the one with focus; a name reaches one only once it is the only window of that name or title.
```

**Workaround.** Close "second" by its unique title first. That changes the program under test.

**Suggested fix.** Add indexed addresses such as Form1#2, and list them in the ambiguity refusal.
Exact title precedence over form names was rejected: another form captioned "Form1" must not take
the stable handle from the form named Form1.

**Fixed.** ForegroundWindow.Pick accepts name#n when no title, form name or floating-tool key
matches the whole value exactly. It counts visible matches in the supplied lifetime list's opening
order, starting at 1; hidden windows do not count. Out-of-range indexes report the count, and an
ambiguity refusal lists each address with its title while retaining the explanation of what auto
reaches. Avalonia 12.1.6's
[ClassicDesktopStyleApplicationLifetime](https://github.com/AvaloniaUI/Avalonia/blob/12.1.6/src/Avalonia.Controls/ApplicationLifetimes/ClassicDesktopStyleApplicationLifetime.cs)
appends on WindowOpened and removes on WindowClosed; no separate ordering is needed. Addresses count the currently visible matches,
so hiding or closing one can change the others' indexes. Headless coverage is in ForegroundWindowTests.
**Live check** (hexide-mcp, 2026-11-18). This commit was cherry-picked onto main at batch 383, which brought separate
`New Form1` instances (#4636), and published linux-x64 Debug. It ran on openSUSE Leap 16 under Xvfb. Form1's Load, in
the default instance only, showed a `New Form1` captioned "second".

```text
dump_visual_tree {"window":"Form1"}   → 2 open windows answer to 'Form1', as two instances of one form do:
                                         Form1#1 ("second"), Form1#2 ("Form1"); each address reaches that window.
                                         "auto" reaches one of them, Form1 ("Form1"), the one opened last.
take_snapshot {"window":"Form1#1"}    → "title":"second"
take_snapshot {"window":"Form1#2"}    → "title":"Form1"
dump_visual_tree {"window":"Form1#3"} → Window 'Form1#3' is out of range: 2 open windows answer to 'Form1'.
interact {"target":"Window","action":"click","value":"60,60","window":"Form1#2"} → clicked the default instance
```

"second" is `#1` because it opened first: the default instance's Load showed it before Load returned and the default
instance itself was shown. The tool descriptions' new sentence wasn't read live, since this session had loaded the
schemas before the build. The `Category=ToolDescription` pins cover it.
