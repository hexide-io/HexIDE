# A sticky-header press reported the text underneath — **CLOSED** (#3840, 2026-11-12)

**Symptom.** [#3840](https://github.com/hexide-io/HexIDE/issues/3840) records a Windows 150% live
check on ab971aca: `interact {"target":"…/Pane[#0]/Custom[Root]/None[TextEditor]","action":"click",
"value":"60,20 to 120,60","window":"ide"}` pressed the sticky `Sub Helper()` header but reported
line 31 as a text position. The retained call abbreviates the target path. The overlay warning did
not prevent the line and column from reading as a text selection.

**Workaround.** Read the landing warning and inspect the actual selection rather than treating the
reported underlying line as selected text.

**Fix.** `CodeWindowPointer` names the sticky header, or another control covering the code window,
and says which document line it covers. Plain-text wording stays unchanged. Headless click and drag
regressions exercise the sticky header and another covering button at 150%. The supervisor's live
check remains: scroll inside a procedure, click and drag from its sticky header, and confirm the reply
names the header and covered line without presenting the press as a text position. No live check
was performed in this WSL run.
