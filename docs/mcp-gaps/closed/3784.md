# Tab tools miss tabs moved into a split document area — **CLOSED** (#3784, 2026-11-12)

**Symptom.** Measured on Windows at 150%, b2dd2ee85, reported in
[#3784](https://github.com/hexide-io/HexIDE/issues/3784). With Form1's designer and code open:

```text
interact {"target":"Window/Custom[MainView]/.../Pane[#0]/Tab[PART_TabStrip]/ScrollViewer[PART_ScrollViewer]/TabItem[Project1 - Form1 (Code)]","action":"expand","window":"ide"}
interact {"target":".../TabItem[Project1 - Form1 (Code)]/None[PART_TabBody]/ContextMenu/ScrollViewer/MenuItem[New Horizontal Document Dock]","action":"invoke","window":"ide"}
dump_visual_tree {"match":"DocumentTabStrip","window":"ide","interactiveOnly":false}
→ Pane[#0] contains Project1 - Form1 (Form); Pane[#2] contains Project1 - Form1 (Code)
close_document_tab {"title":"Project1 - Form1 (Code)"}
→ {"success":false,"error":"No document tab with title 'Project1 - Form1 (Code)'. Open tabs: Project1 - Form1 (Form)."}
get_document_tabs {}
→ {"tabs":[{"title":"Project1 - Form1 (Form)","type":"designer","isActive":true,"project":"Project1","document":"Form1","isModified":true}]}
```

The abbreviated visual paths above are those recorded in the issue. The tab was still visible.

**Workaround.** Find the split tab's own close button with `dump_visual_tree` and invoke it with `interact`.

**Fix.** Traverse every document dock under the live layout root in layout order for listing, activation
and closing; report the focused area's active tab. Listings identify areas with zero-based `area`
indices. Project tab-session capture consequently includes split tabs. Factory-split regression tests
check the service and tool replies headlessly on Linux; live verification is left to the supervising IDE
session, and is not claimed here. The separate accessibility naming issue remains #3787.
