# Carried file tabs omit their identity — **CLOSED** (#3951, 2026-11-14)

**Symptom.** Measured on Windows at c3081cdb7 during #3930's live check, recorded in
[#3951](https://github.com/hexide-io/HexIDE/issues/3951): with `Module=snipmod; snipmod.cpp`
carried by `Probe3930`, `open_file {name: "snipmod", line: 3, column: 5}` and
`activate_document_tab {name: "snipmod"}` returned `project: "Probe3930", document: "snipmod"`.
`get_document_tabs {}` omitted both fields from that tab. Files of one name in two projects
could only be distinguished by their titles.

**Workaround.** Match the tab's title rather than the identity returned by `open_file`.

**Fix.** `HexIdeTools.TabInfo` reads a carried editor's `RelatedDocument` to return its owner's
project name and document name. The description now names carried files alongside forms and modules.

**Verification.** Headless regression compares carried tab identities with `open_file` replies for
two projects carrying `snipmod`, requiring distinct projects. hexide-mcp's live check on Windows
(2026-11-14), with one project carrying `Module=snipmod; snipmod.cpp`: `open_file {name: "snipmod"}`
replied `project` Probe3930 and `document` snipmod, and `get_document_tabs` listed the carried tab with the
same two. The two-project case is covered by the headless test only.
