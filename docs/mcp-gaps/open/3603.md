# On native Wayland, `take_snapshot` leaves out open popups and `boundingRect` is unavailable inside one

**Symptom.** Measured 2026-11-10 with `--platform wayland` (#868) under GNOME 48 on openSUSE Leap 16, at the build that closed #3575.

```
take_snapshot {"window":"ide","inline":true}        (with the File menu open)
→ "note":"Left out of this image: a Border popup 237 × 402, which can't be placed because native Wayland's compositor places a
   popup itself and Avalonia doesn't pass on where it went. ..."

inspect_element {"target":".../MenuItem[File]/ScrollViewer/MenuItem[Exit]","window":"ide"}
→ no boundingRect, and "boundingRectNote":"The control is in a popup, and native Wayland's compositor places a popup itself and
   Avalonia doesn't pass on where it went, so boundingRect is unavailable."
```

The reply is honest, but a menu can't be seen in a capture, and `hover`'s `tipBounds` is absent for the same reason. With no flag,
through XWayland, both work. Read from Avalonia 12.1.4's source and not run under a debugger: the compositor reports a popup's place
in `xdg_popup.configure`, and `PopupImpl.Sink.OnPopupConfigure` reads only its width and height. Filed as
[#3603](https://github.com/hexide-io/HexIDE/issues/3603).

**Workaround.** `dump_visual_tree` lists a popup's controls, and `interact` presses them correctly. For the pixels, capture the
compositor from outside the guest.

**Suggested fix.** Avalonia would need to pass the configure event's position on. Until it does, the placement requested of the
compositor can be read by reflection from `PopupImpl._lastPositioner`, and a popup drawn there with a note saying the compositor
may have moved it.
