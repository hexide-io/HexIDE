# `inspect_element` gives no `expandCollapseState` for a tree node, though the dump lists `expandCollapse` for it

**Symptom.** Measured 2026-11-11 on main at e19377e0c (Windows, 150%) in the Project Explorer, with a project group of two
projects loaded.

```
dump_visual_tree {"window":"ide","match":"TreeViewItem"}
→ ".../Tree/ScrollViewer/TreeItem", "className":"TreeViewItem", "dataContextType":"ProjectGroupViewModel",
  "providers":["selectionItem","expandCollapse"]

inspect_element {"window":"ide","target":"Window/Custom[MainView]/Pane[DockControl]/Pane[Root dock]/List[PART_ItemsControl]/List[#1]/TitleBar[Project Group - OtherGroup]/Pane[Project Group - OtherGroup]/Custom/Tree/ScrollViewer/TreeItem"}
→ "providers":["selectionItem","expandCollapse"], "boundingRect":[724.67,390,178,20], …  and no "expandCollapseState"
```

The tool's description promises `expandCollapseState` for anything with an expand/collapse provider. The node was collapsed in
that call. It was missing just the same on the #3735 branch with the node expanded. There, `interact {"action":"expand"}`
replied `expanded 'Project Group - OuterGroup'`, and `inspect_element` on the same path still gave no state.

The cause: `DescribeProviders` adds `expandCollapse` itself for a `TreeViewItem` with children, because the node's automation
peer offers no `IExpandCollapseProvider`. `Inspect` reads the state only through that provider. A control that owns a context
menu or a flyout is listed the same way, so it should miss the state too. That case is reasoned from the code, not measured.
Filed as [#3742](https://github.com/hexide-io/HexIDE/issues/3742).

**Workaround.** A dump of a collapsed node lists no child `TreeItem`s, but a node with no children looks the same. A
node's `boundingRect` grows when it opens: the group node measured 20 high collapsed and 100 expanded with two projects. Where
the tree binds a view model's `IsExpanded`, `inspect_element` lists it under `dataContextMembers`.

**Suggested fix.** When the peer offers no provider, read the state from the facts that made `DescribeProviders` list the
capability. For a tree node that is `IsExpanded`. For a context-menu or flyout owner it is whether that menu or flyout is open.
Put this in one helper that both `DescribeProviders` and `Inspect` use, so the capability can't be listed again without a
state. A headless test should read a tree node as `Collapsed`, then as `Expanded` after `interact expand`.
