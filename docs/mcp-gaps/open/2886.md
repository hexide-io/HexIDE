# A staying hover in a second window leaves the first still under the pointer

**Symptom (2026-11-02, Windows, #2540's live check, headless first contact).** Two running forms, Form1 ("Hourglass
form") and Form2 ("Default form"):
- `hover(target: "Window", window: "Form1", stay: true)`, then `hover(target: "Window", window: "Form2", stay: true)`.
  Both replied that `'VBFormRuntime' reads as under it (isPointerOver)`.
- `inspect_element(target: "Window", window: "Form1")` then gave `"isPointerOver":true`, and so did Form2's. A real
  pointer is over one window at a time.
- The caller reported that "Form1 still read as pointer-over afterwards, even though the second hover was in a
  different window."

`hover`'s description says pointer-over "stays the hover's until the real mouse next moves", and it doesn't say that a
later hover elsewhere leaves the first in place. The second reply doesn't mention the first window.

**Workaround.** Move the real mouse, which no hexide tool can do (#2666). Untested: hovering the first window again
without `stay` should end its pointer-over, since that hover leaves the window when it finishes.

**Suggested fix.** #2886:
- end the previous staying hover with a pointer leave when the next one lands in another window, and say so in the reply;
- or, at the least, say in the description and the reply that the earlier window still reads as under the pointer.
