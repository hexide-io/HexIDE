# `take_snapshot` with `includeFrame` returns a right-to-left window reversed, and doesn't say so

**Symptom.** Measured 2026-11-16 on Windows at 150%, on #3973's first lane round (`9c204b0a6`), whose right-to-left `MsgBox`
has the `WS_EX_LAYOUTRTL` style.

```
take_snapshot {"window":"Title 1","includeFrame":true}
→ the image: "Title 1" at the left with reversed glyphs, the close box at the right, the icon at the left, and the buttons
  Yes, No, Cancel from the left, each label reversed
```

The screen showed the opposite. Its real pixels were grabbed with the window held on top and not activated: the title at the
right and the close box at the left, the icon at the right, and Cancel, No, Yes from the left, with normal glyphs. It's the
capture, not the window. Windows' own `MessageBoxW` with `MB_RTLREADING`, captured with `PrintWindow` and
`PW_RENDERFULLCONTENT`, comes out reversed in the same way. Filed as
[#4103](https://github.com/hexide-io/HexIDE/issues/4103).

**Workaround.** For a window with `WS_EX_LAYOUTRTL` (read `GWL_EXSTYLE`), flip the image horizontally before reading it. To
confirm the layout, grab the screen's pixels with the window held on top.

**Suggested fix.** When the captured window has `WS_EX_LAYOUTRTL`, flip the image before returning it, and say so in the reply.
Failing that, note that the window is mirrored and the image is reversed.
