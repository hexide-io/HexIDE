# The run-control tools refuse an external debug session that the Debug menu steps and continues

**Symptom.** Read from source at `45c900eee`, not measured live. During an external debug session, `step_into`,
`step_over`, `step_out`, `continue_program`, `break_program`, `run_to_cursor` and `set_next_statement` each reply
`{"success":false,"error":"This command is not available for an external debug session."}`. The Debug menu sends the
same commands to the adapter: `stepIn`, `next`, `stepOut`, `continue` and `pause`. With #2964 it also sends
`gotoTargets` and then `goto`. `stop_project` and `get_debug_state` already work in an external session.

**Workaround (reasoned, not checked).** Drive the Debug menu with `interact`. For Set Next Statement, place the caret first with
`open_file(name, line)`. Then read where the session stopped with `get_debug_state`.

**Suggested fix.** Route each tool to the external session as `ProjectRunnerService` routes the menu. Wait for the
adapter's next `stopped` event, and report the top frame's file and line, as `get_debug_state` reads them. #2968 has
the details, including the module-name-to-path mapping a line-taking tool needs.
