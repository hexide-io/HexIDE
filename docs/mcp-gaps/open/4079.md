# shutdown_ide's reply doesn't say it discarded unsaved edits, and with force false says to poll /health while a save prompt waits

**Symptom.** Measured 2026-11-16 on Windows, with a Debug build of main `80cd5151a`. The IDE was a `--newproject` one,
with Form1's designer tab reading `isModified: true` in `get_document_tabs`.
- `shutdown_ide {}` replied `{"requested":true,"projectStopped":false,"dialogsClosed":0,"note":"Shutdown requested. Poll
  /health until it stops answering to confirm the process exited."}`. The IDE exited and Form1's change was discarded,
  but the reply doesn't say so.
- `shutdown_ide {"force": false}` gave the same reply, word for word. But the IDE didn't exit: a save-changes dialog,
  listing Project1 and Form1, opened and waited. A caller who follows the note polls `/health` for ever.

**Workaround.** Before the default `force`, read `get_document_tabs` for `isModified`. After `force: false`, run
`dump_visual_tree {window: "auto"}`. The prompt is the auto window: `interact` on `Window/Custom/Button[Cancel]` keeps the
IDE and its edits, and on `Window/Custom/Button[No]` closes it.

**Suggested fix.** The unsaved set is known before the close is posted, so the reply can say it:
- with `force` true, list the documents whose changes were discarded, or say there were none;
- with `force` false and unsaved changes, say that a save prompt will open and wait, name the documents, and give the
  next step instead of "poll /health". [#4079](https://github.com/hexide-io/HexIDE/issues/4079).
