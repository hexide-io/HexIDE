# `run_project` often says nothing was printed when the startup form's `Form_Load` printed, and the output is lost

**Symptom.** Measured on 2026-11-06 at 993091535, with the interpreter's own run. Form1's only code is
`Private Sub Form_Load()`, `Debug.Print "load"`, `End Sub`. `run_project` and then `stop_project` were called eight
times over:

- `run_project` replied `"printed":"load\n"` on runs 1, 5 and 6. On the other five it replied `Debug.Print wrote
  nothing since the run began, or since the last reply that reported its output.`, with no `printed`.
- `stop_project` also said nothing was written, every time, so the line is lost, not late.
- `inspect_element` on the Immediate window (`…/TitleBar[Immediate]/Pane[Immediate]/Custom/None[Immediate.Editor]`,
  `"window":"ide"`) read `load` eight times, so Load ran on every run.

The buffer behind `printed` is cleared when `IsRunning` turns true. For a startup form, that is when `RunHandle` is
set, after `VBLoader.RunForm` returns. The interpreter yields only once `DebugController`'s 15 ms time slice has run
out. So a start that reaches Load sooner prints inside `RunForm`, and the clear then discards the line. This cause is
read from the code, not checked.

**Workaround.** Don't read a missing `printed` after `run_project` as "Load printed nothing". Read the Immediate
window with `inspect_element` on its editor, `"window":"ide"`, as above. It keeps every run's output.

**Suggested fix.** Clear the buffer when the run is claimed, where `RunningProject` is set before anything can
execute, and not when `IsRunning` changes. #3229 has the details and a headless test with `TimeSliceMs = null` that
should fail every time today.
