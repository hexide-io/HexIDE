# Right-click context menus appear at the screen origin (#3130)

**Symptom.** On Windows Server 2025 at 150%, `interact {"target":"…/Pane[Watches]/Custom/Tree/ScrollViewer/TreeItem[1 + 1]","action":"click","value":"right","window":"ide"}` opened the ContextMenu at screen (0,0), although the click was at window (384.3,550.7) DIP. The Project Explorer's ContextFlyout did the same. The full paths and external popup rectangle measurements are recorded in [#3130](https://github.com/hexide-io/HexIDE/issues/3130).

**Workaround.** No workaround was verified in the issue. A button-anchored flyout was measured at the correct position, but uses a different placement route.

**Suggested fix.** Feed the click position through Avalonia's raw pointer input, which updates the last screen position used by pointer popup placement. Routed pointer events alone carry the correct event coordinates but do not update that position; the placement target is not the cause.

**Implementation and verification.** Click arrival goes through the window's raw input, retaining the routed fallback used by hover. Headless tests cover ContextMenu and ContextFlyout popup origins within three pixels of the click at 100% and 150%. The [round 1 live check](https://github.com/hexide-io/HexIDE/pull/3148#issuecomment-6650561063) passed both placements at 150% with another window in front, but clicking `Button[Standard.ProjectExplorer]` left its tooltip open seven seconds later.

**Round 2.** Avalonia's NuGet packages contain no C# source. Reading `ToolTipService.cs` at the manifest's source commits for [12.0.4](https://github.com/AvaloniaUI/Avalonia/blob/a8dd6417fd8918570edefdbecd92d16ac7620069/src/Avalonia.Controls/ToolTipService.cs) and [12.0.5](https://github.com/AvaloniaUI/Avalonia/blob/fee9c561ce036e8a3e8cee2397c75ca599b4790d/src/Avalonia.Controls/ToolTipService.cs) confirms that raw Move starts tracking and raw ButtonDown stops the show timer and clears the open tip. Press and release now also go through raw input, using the click's pointer so capture and held moves stay together. A headless regression clicks a tooltip-bearing button and checks that its tip stays closed past the show delay. This entry stays open for the supervisor's live recheck: click the Project Explorer toolbar button, wait seven seconds, and confirm no tooltip appears in a snapshot; retain the Watches and Project Explorer right-click placement checks at 150% with another window in front.
